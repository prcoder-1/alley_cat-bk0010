# Порт игры Alley Cat для компьютера Электроника БК-0010

Перевод на Си игры *Alley Cat* (Bill Williams, IBM PC, 1984) для БК-0010 с блоком
расширения памяти СМК-512. Порт — построчный перевод процедур `CAT.EXE`, а не
реконструкция по описанию: у каждой функции в комментарии стоит адрес исходной
процедуры (`/* 0x08E5 */`), у переменной — её адрес в сегменте данных (`[057B]`).
Подробный разбор оригиналов (PC и Atari) и всех отступлений — в
[docs/analysis.md](docs/analysis.md).

## Требования

* БК-0010(-01) или БК-0011М с **СМК-512** (512 Кбайт: нужны страницы 2…13):
  без платы игра пишет `NEED SMK-512`, с СМК-64/128/256 — `NEED SMK-512 (512K)`;
* загрузка 13 файлов по EMT 36: дискета ANDOS (`make andos`) или эмулятор —
  с магнитофона это непрактично;
* для сборки — `pdp11-aout-gcc` (патченный gcc 14, см. `gcc-KP1801BM1.patch`) и Python 3.

## Сборка и запуск

```sh
make            # bin/: CAT.BIN, HI, файлы сцен и дискета ANDOS ALLEYCAT_V<версия>.IMG
make andos      # только дискета ANDOS
make sizes      # размеры ядра и сцен
make g-mpi      # залить дискету на Gryphon-MPI (GMPI_API_URL) и запустить СМК-512
```

Номер версии (`VERSION`) задаётся в `Makefile`, дата сборки берётся при сборке;
обе выводятся на экране загрузки под надписью «LOADING ALLEY CAT»
(`version.h` генерирует `Makefile`).

`bin/ALLEYCAT_V<версия>.IMG` — чистый `ANDOS.IMG` с файлами игры (`mkandos.py`): FAT12,
800 Кбайт, файлы без заголовка `.BIN`, адрес загрузки — в поле времени записи
каталога, как у ANDOS. Запуск — файл `CAT` из файлового менеджера ANDOS:
ANDOS файл только загружает, поэтому `CAT` лежит с автостартом (грузится с 0760,
слова 0760…0776 = 01000 затирают стек загрузчика).

Запуск в эмуляторе `bk0010-emulator`: ключ `--smk`, рабочий каталог — `bin/`
(оттуда EMT 36 берёт файлы сцен), загрузить `CAT.BIN`. В BKemu (модель
`BK-0010-01_SMK512`) — дискета `ALLEYCAT_V<версия>.IMG`, либо `CAT.BIN` вместе со всеми
файлами сцен в каталоге, откуда эмулятор отдаёт файлы EMT 36.

## Управление

Клавиатура и джойстик работают одновременно, выбирать в меню ничего не нужно.
Буквы действуют в любом регистре (ЛАТ/РУС, заглавные/строчные): важна клавиша,
а не символ.

**Движение кота** (клавиатура БК позволяет держать только одну клавишу, поэтому
диагонали — отдельными клавишами):

| Направление | Клавиши БК | PC |
| --- | --- | --- |
| влево | ← или **Ф** (F) | ← |
| вправо | → или **В** (W) | → |
| вверх | ↑ или **Ц** (C) | ↑ |
| вниз | ↓ или **Ы** (Y) | ↓ |
| вверх-влево | **Й** (J) | Home |
| вверх-вправо | **У** (U) | PgUp |
| вниз-влево / вниз-вправо | только джойстиком | End / PgDn |

Буквы образуют блок под левой рукой:

```
Й  Ц  У        ↖  ↑  ↗
Ф  Ы  В        ←  ↓  →
```

**Джойстик** (порт 0177714, раскладка «Электроника»/Джойвокс): ручка — все
8 направлений, любая кнопка (биты 4–6) — действие.

**Остальные клавиши:**

| Действие | БК | PC |
| --- | --- | --- |
| особое действие (special actions оригинала) | ПРОБЕЛ или кнопка джойстика | Alt |
| пауза | P (снять — любая клавиша или кнопка джойстика) | Esc |
| звук вкл/выкл | СУ+S | Ctrl-S |
| начать игру заново | СУ+R | Ctrl-R |
| выйти в меню | СУ+M | Ctrl-M |
| 9 жизней | АР2+9 | Ctrl-9 |

**Заставка и меню:** заставка заканчивается по любой клавише или по кнопке
джойстика (по отпусканию). В меню уровень выбирается клавишами K, H, T, A
(Kitten, House Cat, Tomcat, Alley Cat); на экране меню сразу выведена памятка по
управлению. Игра начинается по любой клавише или по кнопке джойстика.

## Устройство

* **Ядро** (`CAT.BIN`, 01000…~032000): игровой цикл (`main.c`), кот (`cat.c`),
  пёс (`dog.c`), звук (`snd.c`), очки и ввод (`score.c`), время и клавиатура
  (`hw.c`), текст шрифтом ПЗУ (`text.c`), загрузчик сцен (`ovl.c`).
* **Сцены** — каждая в своей странице СМК-512 (режим Std10, окно 0120000…0157777):
  `TITLE`, `INTER` (возврат во двор: картинки провала, бонус, танец), `ALLEYBG`,
  `ALLEY`, `ROOM1`…`ROOM7`. Файл сцены лежит с 0120000 (до 0144000), её первое
  слово — переход на `ovl_entry()`. Сцены занимают страницы 2…13: страницы 0
  и 1 — системные (RAM-BIOS, резидент ДОС). Файлы читаются EMT 36 в раскладке,
  в которой запущена игра, во временный буфер в видеопамяти и копируются в
  страницы. На время загрузки экран переводится в режим расширенной памяти
  (0177664 = 0230): видна только четверть 070000…077777 с надписью «LOADING
  ALLEY CAT...» и процентами загрузки под ней (по шагам: чтение и копия
  каждого файла), а буфер (040000…063777: сначала HI — сразу во все страницы,
  затем сцены по одной) остаётся невидимым. Раскладку запуска `smk_probe` узнаёт по метке в 0120000: на живой
  плате это Std10 на БК-0010 и Std11 на БК-0011М (режим SYS ПЗУ контроллера
  ставит только на время старта — в нём ПЗУ платы закрывает и регистры БК).
  Игра идёт в Std10 и на БК-0011М: там этот режим отключает ПЗУ монитора 11М и
  верхнее ОЗУ, поэтому после загрузки монитор не нужен (шрифт — свой:
  8x8 BIOS IBM PC `font_pc.s` или шрифт ZX Spectrum `font_zx.s`, выбор — `FONT` в
  `Makefile`). После «СТОП» (плата снова в SYS) сцены не
  перегружаются: сразу включается Std10.
* **HI** — блиттер (`gfx.s`, `gfxtab.s`) и константы ядра (спрайты кота, пса,
  цифры); копия в каждой странице с 0144000. Код блиттера исполняется из ОЗУ
  платы, где нет тактов ожидания видеоконтроллера.
* **Вывод спрайта** — один проход по строке: байт источника читается один раз,
  байт БК собирается сдвигами в регистре, снятие фона и операция (копия, AND,
  KEY, OR, подкраска) идут сразу в видеопамять. Команды операции вписываются в
  цикл при смене режима (самомодификация), края строки правятся после неё.
* **Без мерцания**: стирание объекта (`gfx_restore`) откладывается; следующий
  вывод восстанавливает старые строки вперемежку со своими — строку *y* прямо
  перед рисованием строки *y*, так что пустого места на экране не бывает. Когда
  объект поднимается, строки идут снизу вверх (иначе снятие нового фона затёрло
  бы ещё не восстановленный старый); редкие прочие случаи — через буфер 160 байт.
  Прямая запись в экран, звук, смена сцены и начало прохода цикла сначала
  вызывают `gfx_flush()`. Таблица масок KEY и этот буфер лежат в ОЗУ БК за ядром
  (037000…037637).
* **Тон во время работы**: генератора у БК нет, тон звучит, только пока его
  играет процессор. Блиттер между строками зовёт опрос через вектор `gfx_poll`
  (своя копия в каждой странице); во дворе и комнатах 1–6 это `snd_poll`
  (`sndpoll.s`): после 4 длин куска работы — кусок текущего тона не короче
  3 периодов. Простой в конце прохода (`snd_pass_idle`) добивает проход тоном
  до ~47 мс, так что тяжёлый проход не растягивается за тик.
* **Графика**: в игре экран сжат по X в 4/5 — байт БК *j* содержит пиксели CGA 5*j*…5*j*+3; заставка выводится 1:1 с обрезкой краёв (`gfx_mode`).
  Логика работает в координатах PC; спрайты хранятся в геометрии CGA, но в
  порядке бит БК. Картинка 200 строк — в строках 28…227 экрана.
* **Данные** генерирует `re/mkdata.py` прямо из `CAT.EXE` по описаниям
  `re/data_*.py` (`data_*.c` не править).

## Проверка

* `re/` — инструменты разбора: `dis86.py` (листинг `cat.lst`/`c.lst`),
  `pcemu.py` (эмулятор PC на unicorn: CGA-снимки, трассировка блиттеров, модель
  тактов 8088), `atari/` (распаковка XEX и дизассемблер 6502).
* `test/diff_cat.py` — сверка кота и пса с оригиналом: тот же код собирается для
  ПК (`-DHOST`) и шаг за шагом сравнивается с `CAT.EXE` в `pcemu.py` (переменные,
  ГСЧ, экран).

* `test/diff_room.py` — так же двор и комнаты 1–7: проход за проходом все переменные с адресом `[XXXX]` и экран.

```sh
cd test && make libcat.so rooms
python3 diff_cat.py
python3 diff_room.py all        # или: python3 diff_room.py N [seed] [проходов] [уровень]
```
